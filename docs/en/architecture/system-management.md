# System Management (`internal/system/*`)

Backs the **Linux** GUI category.

| Package | Responsibility |
|---|---|
| `postinstall` | Distro/DE-specific post-installation profiles (`detectProfile`, from the os-release ID, the desktop and the version): Mint Cinnamon/XFCE, Ubuntu 24.04/26.04, Ubuntu Budgie 24.04/26.04 (the Ubuntu list without `gnome-tweaks` and `gnome-software-plugin-flatpak`, which would bring GNOME Software in; on 26.04, which ships VLC, the Flatpak step installs only the web-app manager), Fedora 44 and Fedora 44 Budgie (same actions), Zorin Core/Lite and Pop!_OS COSMIC. Budgie is recognized from `XDG_CURRENT_DESKTOP` (`Budgie:GNOME` on 10.9, `Budgie` on 10.10). Uses `tee`/`debconf-set-selections` instead of `bash -c` string interpolation for things like sysctl config and MS TTF fonts EULA acceptance. Each item is applied on its own (`RunPostinstallAction`); `Action.Applied` detects on the system whether it is already in place (packages via one `dpkg-query`/`rpm -q`, sysctl file, active swap, `fstrim.timer`, Flathub + apps), and the items without detectable state are recorded in `postinstall_applied` after a successful run, together with the machine's `/etc/machine-id` (`postinstall_machine_id`): records made under another machine ID (for example after reinstalling the OS while keeping `$HOME`) or before that field existed don't count, so those items are offered again. On Debian-family systems a package on hold (`hi` in `dpkg`) counts as installed. Apt components are read from enabled `deb` sources only (legacy `.list` and DEB822 `.sources`). The Fedora RPM Fusion step installs only the release packages still missing; the codecs step swaps `ffmpeg-free` for `ffmpeg` and then installs the `multimedia` group, and depends on RPM Fusion. The swap-file step aborts on a symlinked `/swapfile`, matches only an uncommented `/etc/fstab` entry and, when anything fails, deactivates and removes the file again so a later run isn't fooled. An item whose `DependsOn` isn't applied is refused. |
| `fonts` | Install/remove JetBrains Mono, Noto Fonts, Carlito, Caladea, and others. The "JetBrains Mono NF" download is pinned to a specific version (v3.4.0) with SHA-256 checksum verification — not a "latest" fetch. Carlito, Caladea and the Noto fonts come from distribution packages on both families (`apt` on Debian/Ubuntu, `dnf` on Fedora; removal on Fedora uses `rpm -e`, which refuses when another package still requires the font). Each downloaded font lives in its own folder, `~/.local/share/fonts/perci/<font>`, and removing it deletes that folder plus the loose `.ttf` files older versions copied straight into `~/.local/share/fonts/`. An archive without any `.ttf` fails the install. On Debian removal uses `dpkg --purge`, which refuses when another package depends on the font. Installed state is an exact match on the font family names `fc-list` reports. |
| `templates` | Blank document templates (Office, LibreOffice, text, code) in the user's Templates/Modelos folder. Falls back to checking for a literal `Modelos` folder on pt-BR locales when `xdg-user-dir TEMPLATES` doesn't resolve one; creates the templates directory if missing before writing into it. Never overwrites an existing file, and only removes plain file names inside that folder. Failures writing a template are reported instead of ignored. |
| `apps` | Flatpak catalog (`Catalogue` slice in `catalogue.go`) — single-step install/uninstall with visual confirmation. `EnsureFlatpak` (also used by the post-install profiles) installs flatpak when missing and always ensures the Flathub remote in the configured scope; its steps (`FlatpakSetupSteps`) join the caller's own install batch, so installing apps at system scope asks for the password once. A batch where some app failed reports "concluído com avisos" (`executor.ErrCompletedWithWarnings`) instead of success. |
| `androidstudio`, `antigravityide` | Android Studio and the Antigravity IDE installed from a local `.tar.gz` (offered under **Desenvolvimento → IDE**, though the code lives here). Both keep the previous installation until the new one is fully in place and move it back when the final step fails (Android Studio keeps its backup only when the old install is complete — it has `bin/studio.sh` — so a partial extraction never replaces a good backup). Antigravity's menu icon is read from the installed `app.asar` by a small built-in asar reader — no `npx` involved. |
| `update` | Unified `apt`/`dnf` + Flatpak + Snap update pass, run from the **Atualizar Sistema** screen. Flatpak apps are updated in both the user and the system installation: the system installation runs as root inside the same privileged batch as the package manager, Snap and journal (one password for the whole update, without Flatpak asking for its own authorization), and the user installation runs afterwards without privileges. Two cleanups are opt-in checkboxes, unchecked by default: vacuuming journal entries older than 7 days, and removing orphaned packages (`autoremove`) plus unused Flatpak runtimes (in both installations). The package manager runs unattended (`--force-confold`, no interactive prompts). If the Snap, Flatpak, journal or `autoremove` steps fail, the update ends as "concluído com avisos" instead of success. |
| `megasync` | MEGA desktop sync client. Installed from MEGA's official signed apt/dnf repository (GPG-verified), not a manually downloaded, unverified `.deb`/`.rpm`. The signing key is accepted only if the fingerprint of its primary key matches the one pinned in the code; on Fedora the verified key is kept in `/etc/pki/rpm-gpg/RPM-GPG-KEY-megasync` and imported into the rpm database. Safe to re-run (the key is dearmored with `--batch --yes` into a temp file first); uninstalling also removes MEGA's repository and key (on Fedora, the key file and its entry in the rpm database), in the same privileged batch. |

Every install/download flow embedding a `curl | sh`-style upstream installer script runs with `pipefail` set (the one exception is `nvm`'s install script, which isn't compatible with `set -u`/`nounset`).

## Distro/DE Gating

None of these packages implement their own distro detection — they're called from Go methods in `cmd/prci-gui` (bound to the GUI's JS frontend) after a check against `internal/distro.Detect()`/`DetectDE()`. See [Core infrastructure](./core-infra.md#internaldistro).
