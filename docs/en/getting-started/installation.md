# Installation

perci.gnl ships as a single Go binary — a desktop GUI app (built with [Wails v3](https://v3.wails.io)), linux/amd64 only.

## Supported Platforms

### Linux — supported

perci.gnl targets `linux/amd64`, built on Wails v3's GTK4 + WebKitGTK 6.0 stack. The sections below cover installation, runtime/build prerequisites, and exactly which distributions get the full experience (see "Supported Distributions").

### Windows — not supported

There is no Windows build, and none is planned. This isn't a packaging gap — the app's architecture is Linux-specific end to end: privilege escalation goes through `pkexec`/PolicyKit, system package management is hardcoded to `apt`/`dnf`, distro/desktop-environment detection reads `/etc/os-release`, and the GUI itself is built on GTK4 + WebKitGTK 6.0. `install.sh` only ever fetches the `prci-linux-amd64` release asset.

### macOS — not supported

Same reasoning as Windows: the privilege-escalation, package-management, and distro-detection layers are all Linux-only. No macOS build exists.

## Runtime Requirements (Linux)

Unlike a static CLI binary, the GUI needs GTK4 and WebKitGTK 6.0 installed to actually run. These are runtime libraries, not the `-dev`/`-devel` headers needed to build Perci — see "Build from Source" below for those.

**Debian/Ubuntu-based** (Linux Mint, Ubuntu, Zorin OS) — normally already present on a desktop install; if the app fails to start, install them explicitly:

```bash
sudo apt install -y libgtk-4-1 libwebkitgtk-6.0-4
```

**Fedora** — normally already present on Fedora Workstation (GNOME); if needed:

```bash
sudo dnf install -y gtk4 webkitgtk6.0
```

## Automatic Installer (Recommended)

```bash
curl --proto '=https' --tlsv1.2 -fsSL https://raw.githubusercontent.com/oito2/perci/main/install.sh | bash
```

`install.sh`:

1. Detects your CPU architecture — only `amd64` is supported; the script exits with a clear error on `arm64` (see "Supported Architectures" below).
2. Fetches the latest GitHub release tag via the GitHub API (HTTPS only), refusing a tag that doesn't look like `vX.Y.Z`.
3. Downloads the `prci-linux-amd64` asset and the release's `checksums.txt`.
4. Verifies the downloaded binary's SHA-256 against `checksums.txt`, aborting on any mismatch.
5. Installs it to `/usr/local/bin/prci`. When that directory isn't user-writable, `sudo` copies the binary into a root-owned staging file, re-verifies the checksum on that copy and only then moves it into place as `root:root` 0755 — the file downloaded to `/tmp` is never trusted after the password prompt.
6. Links `perci` as a symlink alias to `prci` — both commands work interchangeably.
7. Adds an application menu entry (`/usr/share/applications/perci.desktop` + the icon set in `/usr/share/icons/hicolor/<size>/apps/perci.png`, sizes 512, 256, 128, 64, 48 and 32), so Perci shows up in your desktop's app launcher — not just via `prci`/`perci` in a terminal. The files come from the release's `perci-menu.tar.gz`, verified against `checksums.txt` like the binary (and re-verified by root before extracting). It always installs the blue icon; choosing another color in **Home → Configurações → Ícone do Aplicativo** reinstalls the set (asking for the admin password once). A leftover `/usr/share/pixmaps/perci.png` from older installs is removed. This step is best-effort: if it fails (e.g. no network, or a release older than this change that has no `perci-menu.tar.gz`), the install still succeeds, just without a menu entry.

Requires `curl`, `jq`, `sha256sum` and `tar` to already be present — the script checks for all of them up front and exits with a clear error if one is missing.

## Manual Installation

1. Download `prci-linux-amd64` and `checksums.txt` from the [Releases page](https://github.com/oito2/perci/releases).
2. Verify the checksum, install the binary owned by root inside your `$PATH`, and (optionally) link the `perci` alias:

```bash
sha256sum --ignore-missing -c checksums.txt
sudo install -m 755 -o root -g root prci-linux-amd64 /usr/local/bin/prci
sudo ln -sf /usr/local/bin/prci /usr/local/bin/perci
```

To also check where the files came from, every release carries a build provenance attestation generated by the release workflow — verify it with the [GitHub CLI](https://cli.github.com/):

```bash
gh attestation verify prci-linux-amd64 --repo oito2/perci
```

This manual path skips the application menu entry `install.sh` creates — Perci will only be reachable via `prci`/`perci` in a terminal unless you add one yourself, using [`packaging/perci.desktop`](https://github.com/oito2/perci/blob/main/packaging/perci.desktop) as a template and the icons under [`packaging/icons/`](https://github.com/oito2/perci/tree/main/packaging/icons) (copy one color's `hicolor/` tree into `/usr/share/icons/hicolor/`).

## Build from Source

Requires Go 1.26 or higher, plus the Wails/WebKitGTK build dependencies:

```bash
# Debian/Ubuntu-based
sudo apt install -y libgtk-4-dev libwebkitgtk-6.0-dev

# Fedora
sudo dnf install -y gtk4-devel webkitgtk6.0-devel
```

```bash
git clone https://github.com/oito2/perci.git
cd perci
go build -trimpath -ldflags "-X github.com/oito2/perci/internal/version.Version=v1.0.0" -o prci ./cmd/prci-gui
sudo install -m 755 -o root -g root prci /usr/local/bin/prci
```

GTK4 + WebKitGTK 6.0 is Wails v3's default stack, so the build needs no
`-tags` at all (the older GTK3/WebKit2GTK 4.1 stack is available only as a
legacy opt-in via `-tags gtk3`, which this project doesn't use).

Or, using the provided `Makefile`:

```bash
make build              # builds ./prci with VERSION=dev
make build VERSION=v1.0.0
make install            # builds, then installs to /usr/local/bin with the perci alias
```

## Release Artifacts

Each GitHub release publishes exactly three files, produced by `make release` and published by `.github/workflows/release.yml` on every tag that points to a commit on `main`:

| Artifact | Description |
|---|---|
| `prci-linux-amd64` | The GUI binary itself — no installer package (`.deb`, `.rpm`, AppImage, Flatpak) is produced. |
| `perci-menu.tar.gz` | The application menu entry `install.sh` installs: `share/applications/perci.desktop` + `share/icons/hicolor/*/apps/perci.png` (blue), extracted into `/usr`. Built reproducibly. |
| `checksums.txt` | SHA-256 of both files above, checked by `install.sh` and (for the binary) by **Home → Atualizar Perci**. |

All three carry a signed build provenance attestation (`gh attestation verify <file> --repo oito2/perci`). The workflow builds and tests with a read-only token; only the separate publish job can write to the release.

To build them locally:

```bash
make release VERSION=v1.0.0   # outputs dist/prci-linux-amd64, dist/perci-menu.tar.gz and dist/checksums.txt
```

## Supported Architectures

Only linux/amd64 is published. The GUI uses cgo (GTK4/WebKitGTK 6.0 bindings), so it doesn't cross-compile to arm64 the simple way a static Go binary would — that needs a proper arm64 cross-toolchain and the arm64 versions of the GTK4/WebKitGTK dev packages, which the release pipeline doesn't provision yet. Building from source on an arm64 machine itself should still work, following the steps above.

## Supported Distributions

perci.gnl's post-installation and desktop-environment-aware features are scoped to the distros the author actually runs day to day. Other Debian/Fedora-family distros will mostly work for the distro-agnostic features (dev SDKs, Docker stack, AI context, etc.), but menu items requiring a specific distro/DE combination stay hidden from the "Linux" category outside of these:

| Distribution | Desktop Environment |
|---|---|
| Linux Mint 22.3 | Cinnamon, XFCE |
| Ubuntu 26.04 | GNOME (default) |
| Fedora 44 | GNOME (default) |
| Zorin OS 18.1 | Core (GNOME), Lite (XFCE) |

Arch-family distros are not supported — `internal/distro` only detects the Debian and Fedora families.
