# Managers (`internal/manager/*`)

Sustenta a categoria **Repositórios** da GUI (`manager/gitaccount`, com `manager/repo` e `manager/gitignore` para os arquivos de cada repositório), a tela **Dev Tools → IA: Contextos** (`manager/ai`) e as ações de Backup/Restore em **Docker → Gerenciar Containers** (`manager/db`); veja [Stack Docker de Aplicativos](./appstack.md).

## `manager/ai` — Geração de Contexto IA

Gera arquivos de contexto para agentes de IA num **projeto alvo** (a pasta escolhida com `PickAIContextFolder`) na tela **Dev Tools → IA: Contextos** (`cmd/prci-gui/service_aicontext.go`, parte do `DevToolsService`), para os agentes e guias marcados.

- **Agentes** (`agents.go`): Claude Code, Gemini (CLI e Code Assist), ChatGPT CLI (Codex), OpenCode e Antigravity, uma caixa para cada (todas marcadas numa pasta sem `AGENTS.md`). O `AGENTS.md` termina com `<!-- Perci: generated for … -->`, que `DetectAgents` lê de volta (um `AGENTS.md` antigo conta Codex, Antigravity e os agentes cujos arquivos existem).
- **Arquivos** (`GenerateSharedFiles`): sempre o `AGENTS.md`, os guias marcados em `.instructions/` e o `.instructions/PROJECT.md`; depois, por agente:

  | Agente | Arquivos |
  |---|---|
  | Claude Code | `CLAUDE.md` (`@AGENTS.md` + `@.instructions/PROJECT.md`); `.claude/rules/perci/<GUIA>.md` — uma cópia de cada guia por tipo de arquivo sob um frontmatter `paths:`, para o Claude Code carregá-lo só quando mexe num arquivo correspondente; regras de leitura `permissions.deny` mescladas no `.claude/settings.json` |
  | Gemini | `GEMINI.md` (`@./AGENTS.md` + `@./.instructions/PROJECT.md`); `.aiexclude` (Code Assist) e `.geminiignore` (CLI) |
  | OpenCode | `.instructions/PROJECT.md` acrescentado a `instructions` no `opencode.json` (o OpenCode não segue referências do AGENTS.md); as outras chaves ficam, e o `opencode.jsonc` nunca é tocado |
  | Codex, Antigravity | só o `AGENTS.md` |

  Desmarcar um agente remove os arquivos dele enquanto ainda forem exatamente o que o Perci escreveu (um arquivo editado ou escrito à mão fica, com aviso), a entrada do Perci no `opencode.json` e as regras do Perci no `settings.json`.
- **AGENTS.md** é o `templates/BASIC.md` mais a lista dos guias marcados. Cada entrada cita o arquivo num trecho de código, com a frase "aplica-se a", nunca como import `@`: o Claude Code carregaria todos os guias em toda sessão. Os agentes leem o guia antes de uma tarefa que ele cobre. Com todos os guias marcados, o `AGENTS.md` fica em torno de 11 KB (abaixo do limite de 24.000 bytes por regra do Antigravity e dos 32 KiB do Codex).
- **Regras do projeto** (`project.go`): o `.instructions/PROJECT.md` é criado uma vez e nunca reescrito. Ele é o segundo na prioridade do AGENTS.md (depois das instruções do usuário), e os agentes registram nele as regras que o usuário define para o projeto. Num Aplicar, as linhas de um `AGENTS.md` existente que nenhuma versão do Perci gerou (`templates/legacy/` guarda os conjuntos de regras anteriores) vão antes para uma seção "Moved from AGENTS.md (data)", nunca duas vezes.
- **Bloqueio de leitura** (`claude_settings.go`): uma lista canônica (`templates/ignore/patterns`) — segredos, dependências, VCS, caches, logs, arquivos minificados, áudio/vídeo/fontes, pacotes e binários. Imagens, PDFs e lockfiles continuam legíveis. `dist/`, `build/`, `out/`, `vendor/`, `env/` e `.next/` ficam de fora quando o `git ls-files` mostra arquivos versionados neles. O Claude Code recebe regras `Read(...)` (um padrão de pasta vira `Read(pasta/**)`, `.claude/` é ignorado), e toda regra que uma versão anterior gerou e a lista atual não gera é removida, mantendo as regras do próprio usuário. O Gemini recebe a mesma lista como `.aiexclude`/`.geminiignore`. **O OpenCode não recebe regras**: a configuração `permission` documentada está obsoleta no schema dele, e nenhuma das formas documenta como um padrão de caminho casa. Codex e Antigravity não têm mecanismo no projeto.
- **Tela**: guias agrupados pela base, com os complementos recuados, uma descrição em português cada (`Model.Description`; o `AppliesTo` continua em inglês para os agentes) e um selo de estado vindo de `GuideStatus` — aplicado, desatualizado (idêntico a uma versão anterior commitada, `template_history.go`, protegido por `TestTemplateHistory`) ou editado. Uma pasta sem guias começa no tipo de projeto que os arquivos sugerem (`SuggestPreset`). O **Aplicar** mostra antes os arquivos a criar, atualizar ou remover (`Preview`: a geração real numa cópia temporária, com a lista do git do projeto; links são copiados como conteúdo, nunca escritos através deles).
- O catálogo cobre Bash, Go (com os complementos de servidor MCP e Wails v3), Rust + Tauri v2 (com os complementos Vanilla TS, SvelteKit e React), PHP + Slim 4 (com os complementos PDO, Doctrine DBAL e Eloquent), Moodle, Dart + Flutter, Godot 4, MySQL/MariaDB, TypeScript/Node, Docker/Compose, CI (GitHub Actions), Website, Landing Page Design e os guias de documentação. Todo guia tem a data `Last verified` e termina numa seção `Quality`. Um modelo pode declarar `Requires` (incluído automaticamente, com a base listada antes) e nomes `Legacy` (migrados no Aplicar).
- **Marcadores do Moodle**: `{{MOODLE_VERSION}}`/`{{MOODLE_FULLVERSION}}` são preenchidos pelo `version.php` de um checkout do Moodle (ou `public/version.php`) ou pelo `$plugin->requires` de um plugin; sem nenhum dos dois, viram "unknown (…)" e um aviso aparece — nenhum marcador cru é gravado. A leitura do `version.php` é limitada a 1 MiB.
- **Arquivos gerados e links simbólicos**: gravados com `fsutil.WriteGenerated` — através do link, guardando um `<arquivo>.perci-bak` de uma versão anterior diferente. Um `CLAUDE.md`/`GEMINI.md` que é link para o `AGENTS.md` fica como está.
- **Aprovação da pasta**: a pasta alvo precisa ter sido escolhida no diálogo nativo de pastas nesta sessão (ou ser uma pasta já registrada); caso contrário, a GUI recusa com "pasta não escolhida no seletor".

## `manager/db` — Operações de Banco de Dados

Backup (`Backup`) e restauração (`Restore`) do MariaDB. Sem tela própria na GUI — invocado diretamente pelas ações Backup/Restore de [Docker → Gerenciar Containers](./appstack.md#docker--gerenciar-containers) na linha do MariaDB, contra `appstack.MariaDBContainerName` e `cfg.Docker.MariaDB.DBUser`/`DBPass`. Caminhos de backup/restauração são validados e expandidos (`~`) antes do uso. O backup é um `mariadb-dump --all-databases` com `--single-transaction --skip-lock-tables` (um snapshot consistente sem travar tabelas) e `--routines --events` (rotinas e eventos incluídos). O dump é gravado num arquivo temporário ao lado do destino e só o substitui quando termina.

## `manager/gitaccount` — Contas Git

Sustenta a categoria **Repositórios** (`cmd/prci-gui/service_repositories.go`, `RepositoriesService`). O guia de uso é [Contas Git e repositórios](../guides/workflows/repositories.md). Uma conta (`config.GitAccount`, `git_accounts` na config) é um usuário de um provedor com uma pasta, uma identidade de commits e uma chave SSH:

- **Validação** (`Normalize`, `Validate`): nome e ID (o slug do nome) únicos, provedor conhecido, formatos de host e usuário, porta até 65535, e uma pasta absoluta, existente, que não contém nem fica dentro da pasta de outra conta (comparada também com os links simbólicos resolvidos).
- **Configuração do git** (`Apply`, `Remove`, `Forget`): `WriteGitconfig` grava `~/.perci/git/<id>.gitconfig` (nome/e-mail em `[user]` e `core.sshCommand`) com `git config --file` num arquivo temporário renomeado por cima; um valor `includeIf.gitdir:<pasta>/.path` na configuração global aponta para ele, adicionado e removido só com `git config --global`. O `core.sshCommand` é `ssh -i <chave> -o IdentitiesOnly=yes -o UserKnownHostsFile=~/.perci/git/known_hosts` (mais a porta); um caminho de chave ou de known_hosts com espaços é recusado.
- **Chaves do servidor** (`knownhosts.go`): as chaves oficiais do github.com e do gitlab.com vêm embutidas (`TrustPinnedHostKeys`); um servidor próprio é consultado com `ssh-keyscan` (`ScanHostKeys`) e as chaves só são gravadas depois que o usuário confirma as impressões digitais — o serviço só aceita as chaves da sua última consulta.
- **Chaves SSH** (`sshkey.go`): `GenerateKey` cria um par ed25519 em `~/.ssh/perci_<id>` e nunca substitui um arquivo existente. As senhas chegam ao `ssh-keygen` e ao `ssh-add` por `SSH_ASKPASS` (com `SSH_ASKPASS_REQUIRE=force`), nunca numa linha de comando: o programa askpass é o próprio executável do Perci (`IsAskpassCall`/`RespondAskpass`), que responde um número limitado de vezes, para que uma senha errada falhe de imediato. `AgentHasKey` lê `ssh-add -l`; `UnlockKey` carrega a chave no agente da sessão. `TestConnection` roda `ssh -T` e confere se a saudação cita o usuário da conta.
- **Token** (`token.go`): guardado, lido e apagado com `secret-tool`; o `config.yaml` registra só `has_token`.
- **Repositórios** (`repos.go`): `Discover` percorre a pasta da conta sem seguir links simbólicos nem entrar em pastas ocultas, `node_modules`, `vendor` ou num repositório (um arquivo `.git` conta, para worktrees e submódulos). `ReadRepo` lê só o estado local — `git config --local --get-regexp`, `git --no-optional-locks status --porcelain=v2 --branch`, `git log -1` — até 8 repositórios por vez; a "última verificação" é a data de modificação de `.git/FETCH_HEAD`. `ClassifyRemote` classifica o origin: SSH da conta (`ok`), HTTPS da conta (`https`), nenhum, ou outro dono/host (`foreign`, listado à parte).
- **Rede** (`sync.go`): todo comando de rede roda com `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS`/`SSH_ASKPASS` vazios e `GIT_SSH_COMMAND` = o `core.sshCommand` da conta mais `BatchMode=yes` e `ConnectTimeout=15`, então nunca pede nada; 90 segundos por comando, 30 minutos por clone. `Fetch` roda `git fetch --prune origin` 4 por vez; `Pull` busca, relê o estado e roda `git merge --ff-only @{upstream}`, pulando (sem falhar) os repositórios que não podem avançar.
- **Ações** (`actions.go`, `newrepo.go`): `FixURL` testa a URL SSH com `git ls-remote` antes do `git remote set-url`; `SetRemote` e `Init` recebem um nome de repositório (`grupo/nome` no GitLab; `..` recusado); `CloneURL` aceita só um nome ou uma URL da conta; `DestDir` limita um repositório novo a uma pasta nova ou vazia estritamente dentro da pasta da conta e fora de outros repositórios; um `Clone` que falha apaga as pastas-pai que criou. Todo método do serviço que recebe uma pasta lista de novo os repositórios da conta e só aceita um listado.
- **API do provedor** (`remoteapi.go`): `ListRemoteRepos` lista os repositórios de que o usuário da conta é dono — GitHub `/user/repos?affiliation=owner` com token ou `/users/<usuário>/repos?type=owner` sem, em `api.github.com` ou `<host>/api/v3`; GitLab `/projects?owned=true` ou `/users/<usuário>/projects`, em `<host>/api/v4` — 100 por página, até 10 páginas, tempo limite de 20 segundos. O token vai só num cabeçalho da requisição, e a URL SSH é montada localmente, não tirada da resposta.
- **Exportar/importar** (`transfer.go`): o arquivo é YAML com `version: 1` e as contas com seus repositórios (`path` relativo à pasta da conta, `url` SSH); chaves desconhecidas são recusadas, então o export do Docker não é lido como um. `PlanImport` casa uma conta com uma cadastrada pelo provedor, host e usuário; `Import` mescla nela (só repositórios pendentes novos) ou cria a conta — pasta, chave (`~/.ssh/perci_<id>`, reaproveitada quando existe, senão gerada sem senha), chaves do servidor embutidas, `Apply` — e registra os repositórios em `pending`. `ClonePending` clona um por vez e tira os clonados de `pending`; antes, o serviço roda o teste de conexão.

## `manager/repo` — Identidade Global e Código de Conduta

Identidade Git global (`ConfigureGlobal`/`GetGlobalIdentity`, a aba **Identidade padrão** de Configurar Conta) e geração do Código de Conduta (`CreateConduct`, uma ação por repositório na tela de uma conta: `CODE_OF_CONDUCT.md` na raiz mais o espelho em português em `docs/pt-br/codigo-de-conduta.md`, a partir de modelos embutidos do Contributor Covenant, com o e-mail de contato para denúncias que o usuário digita — preenchido com o e-mail do próprio repositório ou, sem ele, o da conta; nenhum endereço fixo é gravado. Um `CODIGO_DE_CONDUTA.md` deixado na raiz por versões antigas é avisado, não apagado). `ConfigureGlobal` nunca sobrescreve um `credential.helper` já configurado; quando precisa escolher um e o `git-credential-libsecret` não é encontrado, usa `cache` (senha guardada em memória por 15 minutos) e mostra um aviso apontando para **Pré-requisitos → Libsecret Tools**. `Init`, `Clone` e `ApplyLocalIdentityAt` serviam a tela removida Dev Tools → Repositórios e não são mais chamadas pela GUI.

## `manager/gitignore`

Gera um `.gitignore` sob medida para o projeto (`Generate`). O tipo de projeto é detectado pelos arquivos típicos na **raiz** da pasta (`DetectStacks`, um dicionário em `gitignore.go`), sem depender do `.instructions/`:

| Tipo | Marcador | Tipo | Marcador |
|---|---|---|---|
| Go | `go.mod` | Node.js | `package.json` |
| Flutter | `pubspec.yaml` com `sdk: flutter` | Python | `pyproject.toml`, `requirements.txt`, `setup.py` |
| Dart | `pubspec.yaml` sem Flutter | Ruby | `Gemfile` |
| Moodle | `version.php` com `$plugin->component` | Rust | `Cargo.toml` |
| PHP | `composer.json` | Java | `pom.xml`, `build.gradle`, `build.gradle.kts` |
| Shell | qualquer `*.sh` | | |

As seções de editores e de sistema operacional sempre entram; sem tipo reconhecido, entram as seções genéricas (ambiente, logs, build/dependências). Vários tipos podem valer ao mesmo tempo, e um padrão comum a duas seções é escrito uma vez só. Um `.gitignore` existente é **mesclado, nunca sobrescrito**: o conteúdo fica como está e só os padrões que faltam são acrescentados, sob o título da seção — rodar de novo não acrescenta nada.
